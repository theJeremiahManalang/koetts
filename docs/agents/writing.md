# Writing project instructions

Use root `AGENTS.md` only for rules every task needs and explicit task-routing pointers. Put domain invariants beside their owning workspace; put setup commands in the developer guide and executable checks in package scripts.

A context pointer states its trigger and authoritative target. Inline shared rules; disclose branch-specific reference. Keep each meaning in one authoritative location. Prefer observable completion criteria and positive instructions. Remove stale statements, generic templates, and copies of facts cheap to read from configuration.

When changing the harness, validate all pointers and walk through substantial new work, quick questions, approved follow-ups, material scope changes, and explicit bypasses. Record text reading costs separately from model evaluations. Keep reusable personal skills outside the repository.
